# CLAUDE.md — Tickbox

TickBox — to-do list backed by the *visitor's* own Puter account (no backend, no API keys, user-pays). Signed out it is offline-first localStorage; signed in the list is one `puter.kv` entry that follows the user to any browser, and a sign-in adopts the anonymous list rather than discarding it. Sync merges per task by `updatedAt` with tombstoned deletes, so a delete on one device is not resurrected by a stale copy on another; header badge reports Local/Syncing/Synced/Sync failed honestly. Modular ES modules; every kv call is gated behind `isSignedIn()` because kv auto-auth opens a popup browsers block outside a gesture (tickbox.neorgon.com)

**Live:** tickbox.neorgon.com · **Port:** 8859

## Run

```bash
make serve
```

Then open http://localhost:8859. It must be served over HTTP — the app is ES modules, and `file://` blocks them.

## Data

- `localStorage['tickbox:tasks']`

## Conventions

- Zero build step. Plain ES modules loaded by `js/app.js`.
- Header and footer come from the shared kits. Do not add site-local `.neo-footer` or `.header-bar` CSS.
- No single JS file over ~500 lines. It currently holds.

## Gotchas

- **Every `puter.kv` call is gated behind `isSignedIn()`.** kv auto-auth opens a
  popup, and browsers block popups outside a user gesture. Removing the gate makes
  sync fail silently for signed-out visitors.
- Sync merges per task by `updatedAt` with tombstoned deletes. The tombstones are
  why a delete on one device is not resurrected by a stale copy on another — do not
  "clean up" tombstones on read.
- Signing in **adopts** the anonymous localStorage list rather than replacing it.
  That is deliberate; a visitor who used the app signed-out does not lose their work.

## Do not touch

- `js/neorgon-*.js` and `css/neorgon-*.css` — vendored kits, regenerated by `packages/neorgon-ui/sync-*.sh`.
